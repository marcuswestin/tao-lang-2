# DEVENV-STUDIO-AGENT-BROWSER-GATE-TIMES-OUT-UNDER-THE-COMPLEMENT-LANE — Studio agent browser gate times out under the complement lane

- **Status:** Candidate
- **Section:** External
- **Area:** The `studio-agent-browser` gate (`packages/ides/studio-tooling/studio-smoke/studio-agent-browser.test.ts`) when it runs beside the other seven host-only Studio gates in `verify-complement`.
- **Impact:** A landing whose complement hits this failure cancels its hosted `Verify` run and turns auto-merge off, as the route says it must, and then needs a fresh push to run again. The same code passed the gate in the previous complement run twenty minutes earlier and passed alone right after.
- **Evidence:** `.artifacts/logs/verify-complement/2026-10-06T04-06-21-426Z-71237-ddbe82e1/studio-agent-browser.log` on `feat/landing-route-tooling` at `fb32fc5e`: `Timed out waiting for browser expression: document.querySelector('.chat-status')?.getAttribute('data-state') === 'on'; last=false` after 28.4 s, with the lane's `summary.json` recording one lane on the machine and a peak load average of 9 on 18 CPUs. The gate waits at most 30 s for the chat status (`studio-agent-browser.test.ts:167`, via `VerificationTimeouts.resolve(30_000)`). The earlier complement run `2026-10-06T03-46-01-273Z-72825-54bb53b9` passed the same gate in 40.4 s with the same gates beside it, and `./agent unsandboxed studio-smoke packages/ides/studio-tooling/studio-smoke/studio-agent-browser.test.ts` passed it alone in 7.1 s a minute after the failure.
- **Workaround:** Rerun the route (`./agent unsandboxed open-pr --auto-merge` after a new commit); the complement reruns every host gate. Confirm the gate alone with the `studio-smoke` shape above before calling it a regression.
- **Proposed change:** Find what the chat status waits on while eight Studio instances start at once (a shared port, the agent bridge, or the Studio build cache), and either serialize the agent-browser gate behind the smoke gates in the work graph or make its wait proportional to the lane's node count the way other host probes read `VerificationTimeouts`. A `--retry-failed` on the complement command that reruns only the failed gates alone, with the same receipt and status, would also keep a one-gate flake from cancelling a hosted run.
- **Dependencies:** None known. DEVENV-WATCHOS-SWIFT-PROBE-FAILS-UNDER-BROAD-LANES records a sibling probe-under-load failure.
- **Acceptance:** Ten consecutive complement lanes pass the gate, or a failure under the lane names a cause other than the chat status timing out.
