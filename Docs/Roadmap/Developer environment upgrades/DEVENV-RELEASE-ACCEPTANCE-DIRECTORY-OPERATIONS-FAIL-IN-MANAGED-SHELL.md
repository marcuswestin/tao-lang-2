# DEVENV-RELEASE-ACCEPTANCE-DIRECTORY-OPERATIONS-FAIL-IN-MANAGED-SHELL — Release acceptance directory operations fail in the managed shell

- **Status:** Candidate
- **Section:** External
- **Area:** Studio release packaging and IDE extension installation
- **Impact:** This task shell cannot complete a Studio release build or prove a clean VS Code extension install, even after the repository's package and validation gates pass. The missing host acceptance cannot be inferred from those gates.
- **Evidence:** On 2026-09-22, `./dev package-studio-native --release-base-url https://example.invalid/tao-studio --channel stable --output-root .artifacts/build/studio-native` stopped while removing `.artifacts/build/studio-native/service-stage/payload.verification` with `EFAULT: bad address in system call argument`. VS Code 1.137.0 then failed an isolated `--install-extension .artifacts/build/tao-ide-extension.vsix --force` with `EPERM` renaming its temporary extension directory to `tao.tao-ide-extension-0.0.1` under `.artifacts/tests/ide-release/extensions`. The completed `DEVENV-064` recovery established the same class of managed-namespace directory removal and rename denial for generated test artifacts; these release acceptance paths were outside that fix.
- **Workaround:** Run release packaging and a clean VSIX installation in an ordinary host shell with the release credentials and actual HTTPS release URL. Keep the resulting signed artifacts and install evidence separate from repository-only verification. No alternate output or install directory was attempted after these denials in this task.
- **Proposed change:** Give `package-studio-native` a supported staging root whose directory lifecycle works in the managed task namespace, and add a managed-shell-compatible isolated extension-install lane or an explicit host acceptance command that records the result. Diagnose the host boundary before choosing either implementation.
- **Dependencies:** Studio signing and notarization credentials and the real release-host URL are needed for public-release acceptance; a confirmed extension publisher ID is needed for marketplace publication.
- **Acceptance:** From the documented release workflow, a signed and notarized Studio artifact is built and checked, and the packaged VSIX installs and activates in a clean VS Code profile. If a host-only step remains, the command reports that boundary and records the host result without calling local package checks an install proof.
- **Source:** 2026-09-22 Studio and IDE extension release preparation on `feat/studio-editor-release`.
