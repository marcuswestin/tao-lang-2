# DEVENV-STALE-MAINTAINED-BINDINGS-AFTER-MERGE — Maintained native bindings go stale after merging main

- **Status:** Resolved
- **Section:** External
- **Area:** `merge-main`, the `verify-complement` landing lane, and maintained native binding generation
- **Impact:** A merge of `main` that changes the maintained native binding generator leaves the checkout's ignored generated bindings tied to the old generator identity. The next host gate that compiles an app refuses them, so the landing route's complement lane fails on a change that did not touch bindings, posts a failed `Verify (host)` status, and tries to cancel hosted Verify. Nothing tracked is wrong; only the regenerable output is stale.
- **Evidence:** On 2026-10-06, `feat/mac2-teardown-port-flake` merged `main` at `a024a29af`, whose Syntax2 change touched `packages/apps/native-bindings`. The first complement run for PR 39 failed in `_compile-word-flower-app` after 447ms with `The maintained native binding generator changed. Regenerate maintained native bindings with tao bindings generate --maintained.` (`.artifacts/logs/verify-complement/2026-10-06T09-38-10-269Z-23697-75158128/compile-word-flower-app.log`). `./agent native-bindings` then published the generated files with no tracked change, and the rerun passed all 8 host gates. The CI Revolution coordinator's worktree hit the same failure the same day. The refusal comes from the generator identity check in `maintained-native-bindings.ts`. Resolved on `feat/local-main-sync` on the landing route: `open-pr --auto-merge` runs `just native-bindings`, which regenerates only stale output, before it pushes and starts the complement. If the regeneration fails or changes a tracked file, `open-pr` refuses before pushing and names what to commit. A direct `./agent unsandboxed verify-complement` run outside `open-pr` still relies on the generator's own stale check.
- **Workaround:** Run `./agent native-bindings` after merging `main`, then rerun `./agent unsandboxed verify-complement` for the same head.
- **Proposed change:** Regenerate maintained native bindings when their generator identity changed, rather than failing. Either `merge-main` regenerates them after a merge that touched the generator's inputs, or the complement lane runs the regeneration as a prerequisite node beside `_parser-gen`, which already plays this role for the grammar. The generator's own stale check stays as the guard for any path that skips both.
- **Dependencies:** None
- **Acceptance:** After merging a `main` that changes the maintained binding generator, the complement lane passes without a manual regeneration, and a checkout whose bindings are current does not pay for a regeneration.
- **Source:** PR 39 landing and the CI Revolution coordinator's landing, 2026-10-06.
