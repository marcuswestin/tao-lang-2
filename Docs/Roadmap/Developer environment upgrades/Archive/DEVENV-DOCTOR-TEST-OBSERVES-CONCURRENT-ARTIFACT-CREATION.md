# DEVENV-DOCTOR-TEST-OBSERVES-CONCURRENT-ARTIFACT-CREATION — Doctor test observes concurrent artifact creation

- **Status:** Resolved
- **Section:** External
- **Area:** Repository doctor and full verification
- **Impact:** A full `./agent verify` can fail the read-only doctor test because another lane creates a top-level `.artifacts` directory during the test, even though doctor did not write it. This makes a clean checkout's verification result dependent on test scheduling.
- **Evidence:** On 2026-09-24, `./agent verify` failed only `repository doctor > reads this checkout without changing it` at `packages/cli/dev-cli/dev-cli-tests/repository-doctor.test.ts:417`. Its before/after list differed only by the newly created `.artifacts/user` directory. The same file passed immediately afterward under `./agent test-file packages/cli/dev-cli/dev-cli-tests/repository-doctor.test.ts` with that directory already present.
- **Additional evidence (2026-09-26):** A Clerk review verification run failed the same assertion at line418 because a concurrent `.artifacts/tao-check-stamp.json.tao-file-mutation.lock.owner-*` file appeared. Filtering names ending in `.lock` does not exclude these owner files. No doctor source changed. Evidence: `.artifacts/logs/verify-changed/2026-09-26T20-07-21-794Z-97428-cb9fc5d7/cli_dev-cli.log`.
- **Recurrence:** On 2026-09-26, `verify-changed` on `feat/native-tooling-finish` failed the same assertion at line 418 when `.artifacts/standalone-vm` appeared between snapshots. The lane reported two concurrent lanes; log `.artifacts/logs/verify-changed/2026-09-26T21-26-42-765Z-5916-8ef66520/cli_dev-cli.log`. The creating process was not identified. The exact doctor test file passed afterward via `./agent test-file packages/cli/dev-cli/dev-cli-tests/repository-doctor.test.ts`; evidence `.artifacts/logs/dev-test/2026-09-26T21-28-08-278Z-17455-79cd9be5`. This focused pass does not replace the failed lane.
- **Workaround:** None needed after the isolated assertion; historical lane failures remain recorded above.
- **Proposed change:** Implemented on `feat/native-tooling-followup`: invoke production `readDoctorFacts(root)` against a fresh private fixture containing all four artifact roots and seeded files; assert the exact recursive directory entries and unchanged file contents. Retain a separate default-root checkout health test. Remove the racy live Git-status and shared-artifact snapshots.
- **Dependencies:** None.
- **Acceptance:** Repeated full verification from a fresh artifact root passes while other lane nodes create their normal artifact directories, and a deliberate doctor write still fails the focused test.
- **Source:** Initial release QA plan verification on `feat/mvp-release-qa-plan`.
- **Resolution evidence:** Both full `./agent verify --no-cache` executions passed with a fresh doctor fixture on every invocation while other nodes created normal artifacts: `.artifacts/logs/verify/2026-09-26T23-23-31-077Z-18287-d16b88ca/summary.json` (the checkout's first complete run, initially absent runtime/artifact cache roots) and `2026-09-26T23-25-12-922Z-28616-6ad689c4/summary.json` (executed repeat). Temporary mutations in production `RepositoryDoctor.ts` independently created `.artifacts/tmp/doctor-deliberate-write.txt` and overwrote `.artifacts/tmp/existing.txt`; each made only the isolated assertion fail. Logs: `.artifacts/logs/dev-test/2026-09-26T23-29-00-346Z-68031-bb1f1d22/cli_dev-cli.log` and `2026-09-26T23-29-14-106Z-72257-869c8775/cli_dev-cli.log`. Both mutations were removed; the focused file then passed at `.artifacts/logs/dev-test/2026-09-26T23-29-30-015Z-74456-c3efc90a/summary.json`. The assertion covers lasting fixture writes, allowing doctor's intentional temporary writability probes; it does not claim arbitrary host paths are unchanged.
