# DEVENV-QA-TUTORIAL-REPLAY-BUFFERS-PROGRESS — QA tutorial replay buffers progress

- **Status:** Resolved
- **Area:** QA source replay and nested workflow output
- **Impact:** The automatic tutorial replay's parent watches for output while its child front door normally buffers progress until completion, so useful work can appear idle.
- **Evidence:** On 2026-10-06, candidate `4bfb13da4`, QA run `20261006184353212-6ed0d745-db74-45e2-959d-3a1da3549bc1` terminated the source child after 120.1 seconds without output. Streaming preparation progress alone later proved insufficient: run `20261006190051371-e9f78ac9-8bd8-41cf-87ec-55d3c6980258` on `1b8a44f0d` terminated at 197 seconds, 120 seconds after the worker started. Its worker log had two passing cases before the ongoing third case. `TestNodes.ts:142-148` documents that file reporters remain silent across tests; the node's own idle floor allows two longest tests. Both failed packets are retained under `Docs/QA/evidence/tutorial-first-hour/`. This identifies an inappropriate parent output watchdog, not the cause of the separately observed per-test deadline failure.
- **Workaround:** A focused source replay remains available through the normal test-file command.
- **Proposed change:** QA invokes `test-file --verbose` to retain preparation and retry progress. It bounds this captured replay by the existing 600-second total process deadline, without using output silence as a hang signal. An explicit bounded policy keeps that deadline active in diagnostic mode. The test runner's own per-test and process bounds and all assertions remain intact; runaway work still has the parent total deadline.
- **Dependencies:** None.
- **Acceptance:** The QA register fixture verifies command-first argument order, the hard total bound with no output-silence watchdog, immutable resume and successful/failed source receipts. All nine register tests pass. The first streaming recheck passed all three tutorial tests in 91.5 seconds, but the later repeated idle failure prevented treating streaming alone as acceptance. Final run `20261006190454914-8e492d50-b4b4-47c3-98c3-b5aeb2c790d4` passed all three cases on its normal isolated retry in 20.9 seconds; the source command took 254.7 seconds, retaining separate initial per-test timeout and passing retry logs. Its summary's 159.8-second suite time combines both attempts. The final repeat and independent total-deadline review are retained in the latest tutorial packet. The rejected intermediate flag ordering remains historical evidence.
