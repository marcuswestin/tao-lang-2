# DEVENV-ACTIVE-NETWORK-POLICY-KEEPS-OLD-DOMAINS — Active network policy keeps old domains

- **Status:** Blocked
- **Section:** External
- **Area:** Shared harness network configuration and native Studio provisioning
- **Impact:** A session that adds required artifact domains can still fail native verification after regenerating its configuration, blocking managed-session native provisioning even when terminal acceptance succeeds.
- **Evidence:** On 2026-09-26, canonical rules and both generated harness configurations permitted `hutch.blackboard.sh` and `electrobun-artifacts.blackboard.sh`. Nix environment setup provisioned Hutch 0.24.3 successfully. Landing then failed at `hutch install` with `could not resolve Cottontail to load hutch.config.ts: ReleaseDownloadFailed`; log `.artifacts/logs/verify-full/2026-09-26T20-45-28-764Z-27086-1d3e5890/studio-smoke-native.log`. A read-only request to `https://electrobun-artifacts.blackboard.sh/cottontail/releases/0.5.0/manifest.json` returned HTTP 403 with `x-proxy-error: blocked-by-allowlist` in the still-active session. The Hutch artifact origin was also denied.
- **Fresh-session evidence:** On 2026-09-26, branch `feat/native-tooling-finish` retained its initial writable checkout at `593ee84f`. `./agent setup --environment` completed and host capabilities found Hutch. With no default Hutch cache present, authorized landing again failed at `hutch install` with `ReleaseDownloadFailed`; log `.artifacts/logs/verify-full/2026-09-26T21-23-27-592Z-98395-02de00c9/studio-smoke-native.log`. In the same session, the pinned Cottontail 0.5.0 manifest returned HTTP 200 and the macOS ARM64 archive downloaded all 35,125,906 bytes with matching SHA-256 `65983ede8068663adacfe738ea6ae27615642a4af680e0d5d9831af345848ea6`. The archive was retained only as a diagnostic artifact, not installed. The earlier allowlist denial was not reproduced; successful direct downloads do not prove native acceptance. The native canary and remaining host gates did not run after fail-fast. The remote archive check confirmed this branch had not landed.
- **Downloader diagnosis:** At pinned upstream revision `8bb98ace92aa90ce0fb66f0ea0cee2c10bcf7f87`, `src/release_store.zig:2025-2044` initializes proxies from the inherited environment and returns `ReleaseDownloadFailed` for an HTTP status outside 200–299, without exposing the URL or status. The current shell has no `DASH_ARTIFACTS_BASE_URL` override, and each uppercase/lowercase proxy-variable pair agrees. This narrows the remaining blocker to an unreported non-2xx downloader response; it does not establish another allowlist denial.
- **Terminal acceptance:** On 2026-09-26, the normal-terminal landing passed native smoke, native canary, and `verify-full`, then pushed `d5bdeaefd03740d976cc14da01b80688aa6fbe89`. The complete lane took 124.1s; this was not a cold-checkout benchmark. The deleted `feat/native-tooling-finish` branch is preserved as `merged/native-tooling-finish` at `773b671b1725eb3877324b8d93d492af0c518240`. Those changes are already landed.
- **Managed-session follow-up:** On `feat/native-tooling-followup`, based on `59b4ea8067ef`, pinned setup succeeded in the initial writable checkout. An empty task-owned Hutch home still reproduced `ReleaseDownloadFailed`. A byte-transparent relay forwarded to the inherited proxy without changing TLS settings, origin policy, request bytes, or credentials. It captured:
  - `CONNECT electrobun-artifacts.blackboard.sh:443` returned `HTTP/1.1 200 OK`.
  - Hutch then sent bytes `47 45 54 20 2f` (`GET /`), rather than a TLS handshake. Its actual request was `GET https://electrobun-artifacts.blackboard.sh/cottontail/releases/0.5.0/manifest.json`; the application response was `HTTP/1.1 400 Bad Request`.
  - Curl through the same relay began TLS with bytes `16 03 01 01 53` after CONNECT and received HTTP 200 for that URL. HTTP/1.1 and Zig's full user-agent/keep-alive headers also succeeded with curl. The archive again downloaded 35,125,906 bytes with SHA-256 `65983ede8068663adacfe738ea6ae27615642a4af680e0d5d9831af345848ea6`; it was never installed.
  - This demonstrates a CONNECT/TLS transport failure in the published pinned engine, rather than another artifact-origin allowlist denial. No proxy or TLS protection was disabled, and no permission or dependency pin was changed. The trace records only the URL, status, and first five protocol bytes; it excludes credentials and sensitive headers. Evidence: `.artifacts/native-tooling-followup/{proxy-probe,curl-proxy-probe,curl-archive-result}.json`; the reproducer is `proxy_probe.py` beside them.
  - Native provisioning was also exercised with `./agent unsandboxed studio-smoke packages/ides/studio-tooling/studio-smoke/studio-host-control.test.ts downloader-followup`. Only this task's newly created private Hutch clones were emptied; shared `~/.hutch` was untouched. The saved `native-empty-before.json` confirms absent `releases`, `toolchains`, and `cache` directories. The test failed at `hutch install` with the same error, before opening a window; log `.artifacts/logs/agent/studio-smoke/2026-09-26T23-32-07-036Z-93399.log`. This is failed prerequisite evidence, not native smoke/canary acceptance.
- **Workaround:** Normal-terminal native acceptance is established, but managed-session acceptance from an empty cache remains unresolved. Preserve the proxy and TLS protections; do not assume a fresh session fixes it, skip native verification, or seed its cache with a diagnostic archive.
- **Proposed change:** Repair the pinned engine's HTTPS CONNECT path so TLS starts before the origin request, then repeat empty-cache native smoke, canary, and `verify-full`. A package rebuild or pin change requires the Developer's approval; none is applied in this follow-up. Building a diagnostic or repaired engine also needs a compiler: the session denied `ziglang.org`, and no alternate compiler download or policy bypass was attempted. The scoped repair/access request is pending.
- **Dependencies:** Effective session network policy must permit the configured artifact domains, and the pinned Hutch downloader must successfully use that environment.
- **Acceptance:** The pinned Cottontail manifest and archive download succeed under the intended agent policy, and native Studio verification completes from an initially empty cache.
- **Source:** Hook naming, Watchman management, and initial verification performance task, 2026-09-26.
