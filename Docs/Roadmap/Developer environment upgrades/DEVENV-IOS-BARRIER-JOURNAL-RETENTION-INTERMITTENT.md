# DEVENV-IOS-BARRIER-JOURNAL-RETENTION-INTERMITTENT — iOS barrier journal retention is intermittent

- **Status:** Candidate
- **Section:** External
- **Area:** Private iOS managed-loop acceptance and asset-journal persistence.
- **Impact:** Broad hosted verification can fail because the on-disk journal lacks the capture failure recorded in memory after uncertain native worker closure.
- **Evidence:** Hosted Verify run `37706929010`, partition 6, at `eeec39b35` failed `managed-loop-acceptance-ios-runtime.test.ts:1143` in `private iOS downloader barrier missing-close retains its original target and creation generations`. The in-memory retained state, unproved drain and capture-failure assertions passed; the journal's final action had an undefined `captureInspectionFailure`. The test passed unchanged in isolation in 20.4 seconds. The iOS implementation and fixture were unchanged by the Chrome shutdown branch, and the fixture supplies its launcher rather than exercising the new shared test-policy graceful-stop path. Logs in that worktree: `.artifacts/checkpoint/ci-83-retry-dev-cli.log` and `.artifacts/logs/agent/test/2026-10-08T00-22-39-812Z-55703.log`. A possible cause is a late refusal-publication snapshot: the barrier can stop awaiting publication when its deadline expires, while an atomic journal write remains pending and the outer catch writes retained-state evidence. Unique temporary files prevent partial writes but do not order their final renames. A failed final save is another possibility; neither cause is established by the logs.
- **Workaround:** Retain the failed run and run the exact test in isolation before one unchanged broad retry. A passing retry does not diagnose journal persistence.
- **Proposed change:** Reproduce overlapping journal writes with controlled save acknowledgements, including a save that never settles. Order journal publication without allowing an earlier hung write to block prompt uncertain cleanup; preserve each caller's rejection and retain exact target and creation owner generations on uncertainty.
- **Dependencies:** A deterministic persistence reproduction distinguishing late overwrite from failed final save.
- **Acceptance:** The final persisted retained action contains the capture failure under reordered write completion. Pending or rejected writes return promptly with useful uncertainty evidence and keep owners quarantined. Pass the existing retention test and a broad lane without weakening its journal assertions.
- **Source:** Hosted verification and isolated diagnosis during Chrome shutdown landing.
