# DEVENV-SANDBOXED-VERIFY-CHANGED-CANNOT-REMOVE-ENV-FIXTURES — Sandboxed verify-changed cannot remove `.env` fixtures

- **Status:** Candidate
- **Section:** External
- **Area:** The `shared` suite in `verify-changed`, specifically `packages/shared/shared-tests/resource-inventory.test.ts`, whose "record safety" cases write `.env` files into a `mkTestDir` fixture to prove the inventory never reads them.
- **Impact:** In an agent sandbox that denies every `**/.env` path, the fixture cleanup fails with `EPERM: operation not permitted, rm '<checkout>/.artifacts/scratch/resource-inventory…'`, the three cases fail, and the lane stops after that definite failure with the remaining checks not run. A branch that touches nothing under `packages/shared` cannot get a green sandboxed `verify-changed`, and each run strands one `.artifacts/scratch/resource-inventory*` directory the sandbox cannot delete either.
- **Evidence:** `.artifacts/logs/verify-changed/2026-10-06T03-37-45-442Z-55413-815de3e5/shared.log` on `feat/landing-route-tooling`, whose diff against `origin/main` under `packages/shared` is empty. `./agent test-file packages/shared/shared-tests/resource-inventory.test.ts` reproduces two of the three failures alone in the same sandbox; the other 47 cases pass. The same tree passed the suite on hosted `Verify`. The denial is the harness's secret-file rule, not a repository defect: the sandbox refuses the `rm` of a path matching `**/.env` even inside the checkout's own scratch tree.
- **Workaround:** Run the file unsandboxed, or take hosted `Verify` as the proof for the `shared` suite and run the other `verify-changed` nodes by name. Remove the stranded `resource-inventory*` scratch directories from an unsandboxed shell.
- **Proposed change:** Let the fixture name its decoy secret files something the sandbox does not protect, or skip the `.env` writes with a logged reason when `CLI.inAgentSandbox()` reports a sandbox, the way the WDA registration cases in `studio-mac2-test-isolation.test.ts` do. Either keeps the assertion that the inventory does not read secrets while letting the sandboxed lane finish.
- **Dependencies:** Archived DEVENV-TEST-FIXTURE-CLEANUP-DENIED-IN-MANAGED-WORKTREES, which recorded a broader cleanup denial that no longer reproduces; this one is specific to the `.env` name.
- **Acceptance:** A sandboxed `verify-changed` on a tree that does not touch `packages/shared` runs the `shared` suite to green and leaves no scratch directory behind.
- **Source:** `feat/landing-route-tooling` verify-changed, 2026-10-06.
