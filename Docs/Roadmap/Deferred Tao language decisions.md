# Deferred Tao Language Decisions

This inventory preserves the useful design space from the former `MVP-triage` sketches without keeping 30 non-executable Tao files active. The sketches were intentionally broad and overwhelming; none of their options is normative unless an active specification says otherwise. Their detailed historical forms remain available in Git history under `Apps/MVP-triage/`.

Navigation and presentation decisions live in `Docs/Roadmap/Add navigation and routing MVP/Follow-ups - Add navigation and routing MVP.md`. The entries below are future language-design projects, ordered by their original dependency sequence. Rows the WordFlower tranches have since settled say so inline; shipped syntax is described in `Docs/Spec/`, and the next unbuilt slice is expressed in `Apps/WordFlower/2 - Next` after each tranche is cut.

| LANG-031 | Package-exported destinations               | Deferred by the unified view amendment (`Docs/Roadmap/Tao Revolution/Decisions.md` §9–§10): restorability is inferred purely from usage, so a package author can silently break consumers by adding an unserializable parameter to an exported view. A `public destination` marker stating the serialization contract at the export is the open door if that proves painful in practice; pure inference is the decision until then.                                               |
| LANG-032 | Arrangement-only view distinction           | Deferred by the unified view amendment: the language no longer distinguishes arrangement-only wrappers (`Centered`) from content-owning ones (`Section`). If a future rule needs the distinction — a lint, a design-tool affordance — it returns as a property derived from the render tree (does the body render anything besides `@@content`?), never as a keyword.                                                                                                             |
| LANG-033 | Custom-host read declarations               | Deferred by the host-read tranche. MVP read/require sets are fixed by stdlib host families and presentation modes. If package-authored component-kit hosts need to declare their own sets, design a host-side contract that preserves usage-site diagnostics, direct-only reads, protocol versioning, and package evolution; do not add user syntax until a forcing host exists.                                                                                                  |
| LANG-034 | Package-extensible host-slot vocabulary     | Deferred by the host-read tranche. `Title` and `Toolbar` are prelude-owned supplied slots. Whether packages may extend the vocabulary for their own hosts must settle naming, collision, visibility, compatibility, and how a consumer proves that a host recognizes the slot. It must not turn prelude-owned typed slots into an untyped open metadata bag.                                                                                                                      |
| LANG-035 | Additional host-facing slots                | Deferred until forced: `Badge`, tab/window icons, detents, appearance, subtitle, status, and other platform chrome traits. Each candidate must prove that it is stable self-description rather than presentation policy, identify a real host and app feature, and define native/basic/web behavior before joining primitive `scene`.                                                                                                                                             |
| LANG-036 | Call-site host-slot overrides               | Explicitly rejected for the current contract: presenters read the directly presented scene's own reactive fills. Reconsider only if a forcing feature proves that two presenters legitimately need different values for the same occurrence. Any future design must remain visibly presentation policy, avoid preference bubbling, and preserve declaration-owned defaults and usage-site requirement checking.                                                                   |

## Tao Revolution pressures to revisit

- **Post-MVP — computed-row mutation (LANG-009).** Decisions §6 retains contributing rows behind a
  group; §5 gives named transactions atomic, caller-scoped multi-row writes. Prefer a named
  transaction over direct write-through on a computed row when Skillet or Hearth makes one folded
  shopping line change several source rows. That gives caller and per-row authority checks, one
  commit, and a named operation for later audit without making an ordinary tick cumbersome. Decide
  the exact rule with a two-account, partial-failure journey; the current §6 “written through”
  wording leaves the boundary ambiguous. Skillet's folded `GroceryRow` binds fields directly, while
  Hearth passes a folded line to `SetDone(Item HearthItem)`; reconcile both demos when that slice runs.
- **Deferred/watch — semantic destination separate from mounting (LANG-022).** Decisions §10
  deliberately puts address and placement in one `link`. Revisit only if restoration, incoming
  links or reminders, or keyed multi-window navigation show that one product destination needs
  several app-owned placements that `link` cannot express clearly. Use a real Wayfare or Hearth
  journey before changing the model.
- **Post-MVP — precise recovery state (LANG-021).** Decisions §5 distinguishes `missing`,
  `unauthorized`, and `error`; §10 recognizes an unavailable provider during restoration. These
  should not label a known document “missing” when it simply was not downloaded on this device and
  the device is offline. Wayfare's offline PDF is the forcing case; prove the state and recovery
  path against a provider before adding a new case.

## Additional Preserved Use Cases

The deleted `Apps/MVP/` exploration also contributed these future cases:

- Conditional chrome tied to active selection, tracked as `DEF-NAV-012`.
- Direct package references without imports, retained under LANG-002 for later resolution design.
- AI/package actions, field-bound inputs, `blur self`, and overlay families such as action, input, form, menu, and mode. These remain examples for LANG-016, LANG-018, LANG-019, and LANG-020 rather than navigation requirements.
- Case-valued state shorthand such as `state IsActive/IsInactive`, omission of `=` in typed state initialization, query/list render elision, and local editable copies of entity fields. These remain examples for LANG-004, LANG-008, and LANG-019.
- Asset literals such as `./images/hero.png`, `../shared/icon.svg`, and `@package/images/hero.png`, with future metadata such as `.Decorative false`, `.DirectionVariant rtl ...`, and `.LocaleVariant es-US ...`. These remain examples for LANG-025.

When one of these becomes active work, create a focused roadmap project with a small authoritative Tao fixture instead of restoring the entire triage matrix.

## Surfaced by running Tao apps on a device

The Tao Studio companion work put WordFlower and HNReader on a real phone beside the same cells in Studio's browser canvas, which forced three questions the canvas alone never asked. Each is described with its evidence in [Slice 2 - Everyday development canvas](./Tao%20Studio%20companion%20app/Slice%202%20-%20Everyday%20development%20canvas.md) under "Discovered and not addressed"; they are listed here so a language worker finds them from this side too.

- **Whether `fill` is the right container default (LANG-017).** `Col` and `Row` default to `[content top stretch, fill]`, so on a device every container shares its parent's main axis while the browser canvas measures the same tree to its content. The divergence itself is a canvas-fidelity defect and fixable without touching the language; whether apps should be written against a `fill` default or ask for it explicitly is the language question underneath, and it changes every existing layout.
- **Whether a query filter naming a deleted row throws or matches nothing (LANG-008).** It throws today, from `relationId` in `TR-data-schema.ts`, which a screen hits by re-evaluating its own filter after deleting the row it was showing. "Matches nothing" would let the screen render its own empty state; keeping the throw makes guarding an app-authoring rule that WordFlower should demonstrate.
- **Whether a scenario and a preview are one declaration or two (LANG-028).** A `scenarios` block currently mixes what describes the run — fixture, subject, appearance, network — with what only frames a preview in Studio's canvas, notably `device`. Splitting them so a `scenario` owns the run and one or more `preview` entries own the frame would make the rule structural rather than a list of which clauses a device honours, and would let one scenario be previewed at several sizes without repeating its fixture.
