## Four recommended production mechanisms

1. **Preview-first compilation:** cached current tooling only for a known isolated versioned Tao
   edit in an otherwise consumed graph. Immutable source overrides, source versions/epochs and
   classified invalidation. Unknown/multiple/stale changes, additions/deletions, configuration,
   dependencies, package boundaries and native inventory go authoritative.
2. **Bounded full work after authenticated child paint:** exact origin/window/app/cell/instance/
   compile/manifest identity and two child animation frames. Latest pending work, one-second quiet
   delay, ten-second maximum anchored to first pending work, error/rejection recovery and final
   close flush/cleanup. Already-running synchronous full work cannot be preempted by this scheduler.
3. **Compiler-owned direct padding:** one finite nonnegative scalar pad literal in Design.tao,
   browser previews, publication checks off. Exact syntax/bytes outside the literal; unique runtime
   source/path/owner/member/index/prior-value/range/baseline guards; immutable provenance shifts for
   different-width literals. Unsupported edits fall back to normal compilation. New preview realms
   await authoritative generated bytes before registration; unchanged stale identities still fail.
4. **Within-attempt native inspection reuse:** integrate with main's existing memo and locked
   recovery, prove avoided work, retain an independent final freshness audit. If current main now
   removes the repetition, retain its owning implementation instead of layering a redundant cache.

Recommend normal production enablement without POC enabling flags, with diagnostic opt-outs.
Publication checks stay on by default. Do not silently extend the tested publication-off browser
style path into native or checked-mode acceptance; settle material product decisions with Developer.

## Later architectural work

- Worker isolation AND independent interactive admission: persistent background full tooling/validation
  worker, its own mutable workspace, immutable generation inputs, one latest pending request, stale
  result rejection and a short publication boundary. Moving emission alone does not bypass the
  awaited coordinator drain and generation mutex. Error/restart/close/eventual-diagnostic parity.
- Shared immutable tooling/preview snapshots: config/package/sidecar/native identity, measured avoided
  preparation, no shared mutable linked ASTs across overlapping builds.
- Dependency-directed validation/compilation: split global/local reports, explicit reverse dependencies,
  unresolved/membership/package/structural cold parity, then output-plan/emission reuse.
- Broader compiler-owned style/token delivery, followed by selective consumed-style subscriptions only
  if larger-app/many-cell fan-out is measured; current whole-app 40 ms does not establish that bottleneck.

Each needs measured cost, API owner, invalidation contract, smallest prototype and parity tests.
100–150ms is a warm-median aspiration, not a guarantee for general saves during full processing.
