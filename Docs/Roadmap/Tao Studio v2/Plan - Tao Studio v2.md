# Plan - Tao Studio v2

Status: implementation ledger for the landed v2 foundations. This document distinguishes live product
wiring, contract-tested code, and native behavior that could not be exercised in this environment. A
generated source file or passing unit test is not described as a running macOS product.

## Decision amendments

The implemented grouped scenarios, typed foreign views, action failures/transactions, containment, capture,
and `runs latest` wording are recorded as proposed amendments in this directory. They do not edit or
replace `Docs/Roadmap/Tao Revolution/Decisions.md`; Ro still owns adoption into that authoritative file.

## Validation record

Focused parser, scoping, validator, formatter, compiler, source-action, Studio, code-editor, runtime,
runtime-toolchain, and developer-automation suites cover the rows above. Release-mode Tao generation and
browser bundling cover the executable Tao root, Files portal, and host bridge; native staging requires that
release bundle rather than the development fallback. The packaged service has also been bundled and
installed from the frozen repository lock in isolated test payloads. The final repository-wide
`./agent verify` gate passed all 18 suites and all 1,536 tests.

Native validation is a separate gate. Hutch, signing/notarization credentials, and an HTTPS artifact host
are unavailable here, so none of the repository tests proves a running signed/notarized Electrobun app or
differential update.

## Next integration gates

1. Install the pinned Hutch toolchain and exercise the actual project picker, windows, menus, shortcuts,
   iframe/WebSocket bridge, packaged standalone service, signed/notarized DMG, and differential update.
2. Run the complete multi-group browser interaction pass, including retained independent cell state and
   offscreen suspension across recompiles.
3. Continue the Tao-client strangler by exposing active-file/content, selected-render, and active-cell host
   values to Tao; then mount the compiled editor boundary and migrate inspector/scenario controls without
   claiming the TypeScript workbench is gone early. Add view-instance persisted-state keying before claiming
   persistent folder expansion.
4. Finish imported-scenario and `run App at Destination(...)` behavior, fixture-through-action setup,
   capture-to-authored-fixture/scenario promotion, and the remaining decided design-system UI.
