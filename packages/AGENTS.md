# Working Across Packages

Implement language features as vertical slices. Use the same focused feature name in each participating parser, validator, formatter, source-actions, compiler, and runtime file; do not add empty stages or catch-all modules.

## Ownership

- Put expected Tao semantic and source-shape diagnostics in the validator. Compiler codegen assumes validated input and uses assertions only for local type contraction.
- Every diagnostic sentence lives in a `*ValidationMessages` object beside the validator that emits it; validators never inline a sentence at the `ctx.error(node, message)` call, and tests assert through those same factories rather than retyping the text. Diagnostic text and emission order are product surface: a wording change is a factory change, and one factory entry is the single place a sentence is spelled.
- Use `AST.*` from `@parser` for parser-owned structure and traversal. Put shared semantic helpers in `@ast-utils`; package consumers must not call Langium AST utilities directly.
- Use shared `Switch` helpers for union dispatch instead of native `switch`. Prefer generated `AST.is<Type>` guards for grammar-declared unions. Whether this rule should also ban equivalent `if` / `else if` chains over one `.kind`, `.type`, or `.$type` discriminant is explicitly deferred: `packages/dev/dev-src/repository-tests/kind-chain-demo.ts` measures the current scope, but it is not a gate. Settle that policy before wiring its report into `repo-lint` or weakening this instruction.
- **A grammar keyword never starts with a capital letter.** Tao's member, slot, field, and property names are capitalized, so promoting a capitalized word to a keyword silently forecloses it as a name everywhere in the language — including in the Prelude, which is where the primitive families declare their members. This is not a style preference; it has already cost us. `Key` and `Duration` were global keywords, which made `Key shortcut is none` undeclarable on `primitive command` until they were removed. Parse such a word as `ID` and validate its spelling instead: `ToastPresentationOptions` in `navigation.langium` and `ForeignViewImplementation`'s `content=ID` in `views.langium` are the two worked examples. The same care applies to lowercase words a design, layout, or test vocabulary already uses — `primary` is a layout tag and a design token, so the shortcut modifier is an imported name rather than a keyword; and a `title` keyword for the `(title)` trait collided at once with `expect navigation title` and the `[title]` design bundle, so that trait parses as a validated word too. Before adding any keyword, `rg` the word across `Apps/`, `packages/stdlib/`, and `Docs/Spec/`.

## TypeScript And Tests

- Use shared wrappers such as `CLI`, `FS`, `HCI`, `Platform`, `Time`, and `@shared/test` instead of direct platform or test-runner APIs. Loader-constrained config files are the narrow exception.
- Never write `new Error(`. Throw through `Errors.throwUserInput`, `throwUnexpected`, or `throwHostEnvironment`; where an error object must exist unthrown (a rejection, an emitter, a callback) build `new Errors.<Category>Error(...)`, wrap an unknown with `Errors.asError`, and cancel with `Errors.abortError`. `packages/runtime` uses `TR-errors` the same way. Both spellings are gated by `repo-lint`, whose only allowlist entries are emitted script text and tests that feed a raw error in; the `error-handling` skill owns the classification.
- `just _repo-lint` ratchets that rule: a value import from a `node:` module, a global console call, a direct read of the process object, or a Bun convenience call (`sleep`, `randomUUIDv7`, `semver`, `TOML`) outside `packages/shared` and `packages/runtime` needs its allowlist entry in `repo-lint.ts`, and the entry goes stale when the file is fixed. Type-only `node:` imports pass. Bun's server and bundler APIs — `Bun.serve`, `Bun.build`, `Bun.resolveSync`, and `Bun.file` when it serves a file — are sanctioned in `dev`, `studio`, and `update-server`, where a wrapper would only rename them. `node:crypto` hashing and signing and `node:net` sockets have no wrapper yet; a new use goes behind a `Platform` seam rather than onto the allowlist.
- Search `@shared` for an existing helper before adding one, and put a helper two packages need in `@shared` rather than in both. Small duplicates accumulate silently; where a copy must exist because `packages/runtime` imports nothing from `@shared`, name the shared original it mirrors and keep the two in step.
- Keep each module's public surface focused on one main concept. Export helpers only for real cross-file or package boundaries.
- Prefer behavior tests.
- A jest end-to-end test in `runtime-toolchain` earns its place only when it needs a native or module override, asserts generated-code shape, or exercises the harness itself. New behavior coverage lands in Tao as a `.test.tao` journey; existing jest suites migrate opportunistically when touched. Do not schedule a wholesale rewrite.
- `just dead-exports` fails on exports nothing imports, and runs in `verify` as well as `verify-full`. The fix is usually to drop the `export` where the symbol's own module is its only user; an export something outside the TypeScript import graph really reaches is re-exported instead from a file in the declaring package named for which consumer reaches it, and that file is added to the package's entry points in `config/knip.json`. It counts test-only usage as usage, so it cannot judge a symbol only its own tests reach.
