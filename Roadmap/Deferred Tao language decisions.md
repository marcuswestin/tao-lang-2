# Deferred Tao Language Decisions

This inventory preserves the useful design space from the former `MVP-triage` sketches without keeping 30 non-executable Tao files active. The sketches were intentionally broad and overwhelming; none of their options is normative unless an active specification says otherwise. Their detailed historical forms remain available in Git history under `Apps/MVP-triage/`.

Navigation and presentation decisions live in `Roadmap/Add navigation and routing MVP/Follow-ups - Add navigation and routing MVP.md`. The entries below are future language-design projects, ordered by their original dependency sequence. Rows the WordFlower tranches have since settled say so inline; syntax that ships today is described in `Spec/`, and syntax that is decided but unbuilt is expressed in `Apps/WordFlower/2 - Next`.

| ID       | Decision                                    | Preserved options or constraint                                                                                                                                                                                                               |
| -------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LANG-001 | Project, package, and visibility shape      | Explicit project declarations; app/package-primary metadata; declaration visibility prefixes. Visibility is now settled as `file`, `package`, `workspace`, `public`.                                                                          |
| LANG-002 | Imports, requirements, install, and publish | Source-level `requires`; manifest-owned dependencies; CLI-owned dependency metadata. Preserve bare package imports, relative imports, package aliases, lockfiles, and app/package publishing use cases.                                       |
| LANG-003 | App capabilities                            | The target MVP includes explicit `Design` and `Datasource` app properties. General capability bundles and ambient `app.theme`, `app.data`, `app.strings`, and `app.assets` access remain unsettled options rather than part of that contract. |
| LANG-004 | Type and enum declarations                  | String-valued enums; identifier cases; inferred scalar types.                                                                                                                                                                                 |
| LANG-005 | Typed constructors and literal inference    | Explicit space-applied constructors; contextual bare literals; constructors only when context is missing.                                                                                                                                     |
| LANG-006 | Item, list, union, and overlay values       | Partly settled: a type instantiates with a bare block and `with` patches an existing value. Open: collection-specific operators, unions, and collection merging.                                                                                                                                |
| LANG-007 | Data fields and relationships               | Unique field types with inferred cardinality; fully explicit fields; collection-owned relationships.                                                                                                                                          |
| LANG-008 | Queries and guards                          | Settled: named queries and block-scoped guards over a single subject ship today. Open: query-attached state branches and general case matching.                                                                                                                                                      |
| LANG-009 | Mutations and transactions                  | Omit defaulted fields; transaction blocks; provider-gated write syntax; relationship `link`/`unlink`; conflict policies such as last-write-wins.                                                                                              |
| LANG-010 | Providers and runtime targets               | Capability manifests; inline datasource capability switches; runtime-target-owned provider selection.                                                                                                                                         |
| LANG-011 | UI declaration roles                        | Separate `view`, `frame`, and `layout`; contextually omit visibility; consider but do not assume a shared `component` declaration. Presentation roles are specified separately.                                                               |
| LANG-012 | Render invocation and elision               | Explicit brace blocks; angle blocks; render elision inside declarations.                                                                                                                                                                      |
| LANG-013 | Combined style and layout specs             | Unified `[]` specs are settled. Preserve the remaining questions of merge precedence, named-spec composition, and which modifiers may be inline-only.                                                                                         |
| LANG-014 | Design tokens and recipes                   | Flat tokens/specs with recipes; categorized blocks; recipes generating semantic components.                                                                                                                                                   |
| LANG-015 | Render slots and keyed content              | Named slots with defaults; invocation-only slot fills; settle render blocks first. Keep keyed object syntax distinct from visual render slots.                                                                                                |
| LANG-016 | UI primitive boundary                       | Compact Tao-owned primitives; smaller primitives plus recipes; first-class native bridge components.                                                                                                                                          |
| LANG-017 | Layout controls                             | Unified layout tokens; dedicated clauses for complex controls; decide after combined specs. Preserve wrapping, overflow, scrolling, alignment, sizing, and compression cases.                                                                 |
| LANG-018 | Visual layers and portals                   | Partly settled: overlays and toasts are presentation modes resolved against the nearest nav, not declared hosts. Open: layers, portals, popovers, one Modal abstraction, and overlay families.                                                                 |
| LANG-019 | State, actions, and functions               | Typed state plus concise inline events; named actions; expression-bodied actions. Immutable `let` is settled; reusable code uses functions or specialized declarations.                                                                       |
| LANG-020 | Events, lifecycle, and automation           | Declared events with `does`/`did`/`on`; inferred event names; automation-owned app/network/time hooks.                                                                                                                                        |
| LANG-021 | Errors and boundaries                       | Result values plus try/catch/finally; exhaustive case matching; boundary-only MVP.                                                                                                                                                            |
| LANG-022 | Routes and deep links                       | Separate route values; UI-attached route metadata; derived routes with stable public aliases. Internal mounted paths must not become public URLs.                                                                                             |
| LANG-023 | Accessibility and localization              | Project policies; UI metadata and simple string bindings; defer to app-capability shape.                                                                                                                                                      |
| LANG-024 | Motion                                      | First-class motion policy and recipes; style-only motion; runtime facade only. Reduced motion must remain expressible.                                                                                                                        |
| LANG-025 | Assets, permissions, and bridges            | Separate declarations; app-capability ownership; tooling-only bridge generation. Preserve relative and package asset paths plus accessibility, locale, and direction-specific asset variants.                                                 |
| LANG-026 | Semantic stdlib types and units             | Partly settled: `N.seconds` is the first unit literal. Open: built-in versus package-owned semantic types, and constrained typed operations such as `random Duration between 100.ms and 300.ms`.                                                               |
| LANG-027 | Testing                                     | Settled: user-oriented Tao tests with tag, text, label, and placeholder selectors ship today. Open: focused render checks, and CLI-owned filtering and runtime flags.                                                                                                                                                        |
| LANG-028 | Scenarios and visual artifacts              | First-class scenarios/design checks; test fixtures; design-CLI-owned artifacts.                                                                                                                                                               |
| LANG-029 | Debugging and source maps                   | Source declarations plus direct tests; CLI-only configuration; defer to testing. Preserve source maps, semantic reducer traces, and Studio inspection.                                                                                        |
| LANG-030 | Tooling and scaffolds                       | MVP-local recipes; `tao create`; `tao dev`. Finalize only after app, design, test, publish, bridge, schema, and debug surfaces settle.                                                                                                        |

## Additional Preserved Use Cases

The deleted `Apps/MVP/` exploration also contributed these future cases:

- Conditional chrome tied to active selection, tracked as `DEF-NAV-012`.
- Direct package references without imports, retained under LANG-002 for later resolution design.
- AI/package actions, field-bound inputs, `blur self`, and overlay families such as action, input, form, menu, and mode. These remain examples for LANG-016, LANG-018, LANG-019, and LANG-020 rather than navigation requirements.
- Case-valued state shorthand such as `state IsActive/IsInactive`, omission of `=` in typed state initialization, query/list render elision, and local editable copies of entity fields. These remain examples for LANG-004, LANG-008, and LANG-019.
- Asset literals such as `./images/hero.png`, `../shared/icon.svg`, and `@package/images/hero.png`, with future metadata such as `.Decorative false`, `.DirectionVariant rtl ...`, and `.LocaleVariant es-US ...`. These remain examples for LANG-025.

When one of these becomes active work, create a focused roadmap project with a small authoritative Tao fixture instead of restoring the entire triage matrix.
