# Taking over a project

- Read the predecessor's checkpoint (`.artifacts/checkpoint/<project>.md` in its worktree) first; copy it into your own worktree, because `.artifacts` is ignored by Git and a cleanup session may remove the predecessor's checkout.
- Tell every in-flight session once that reports now come to you, and ask each for a one-line status: what it measured, what it is changing, its ETA. The predecessor may already have done this; coordinate so sessions hear it once.
- A message to a session in a different permission mode is held for its user's approval and expires undelivered; the delivery notice says so. Tell the Developer which sessions you cannot reach rather than resending.
- Confirm your own model and effort against the brief's gate before doing anything else, and say so in your first report.
