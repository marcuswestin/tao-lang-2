# Progress Report

Give the report immediately and keep it concise.

- Estimate both the percentage of total effort remaining and the wall-clock time to the next requested stopping point. Use a range when host services, verification, or unresolved failures make a single estimate misleading.
- Name what is complete, what is currently being tackled, and the few material items still on the critical path.
- Distinguish active engineering work from waiting on a host service, external approval, or required user decision.
- Base estimates on observed scope and validation cost. State the main assumption when it materially affects the estimate; do not imply precision the evidence cannot support.
- Treat the report as an intermediate update. Resume the active task immediately after reporting. Pause only when Ro explicitly asks to pause or stop, or when required input prevents all useful progress.
