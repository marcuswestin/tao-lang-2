# Appwrite + Legend State experiment

The adapter uses Appwrite email/password sessions and a free serverless TablesDB table for the shared notes contract. Legend State v3 `syncedCrud` keeps optimistic notes in AsyncStorage and persists pending writes for retry. A dedicated Appwrite Realtime client uses a short-lived account JWT to subscribe to this table's row events and refresh the account-filtered note list on incoming changes. It renews the socket before JWT expiry and retains a 30-second poll for missed events and offline recovery. The installed SDK's older `client.subscribe` path makes an uncaught `window.localStorage` access when a socket connects; the dedicated `Realtime` class catches missing storage and sends the JWT in the native WebSocket header. Device delivery of Realtime events still needs acceptance testing. This is an Expo Go experiment, not a Tao datasource or an AccessRules implementation.

## Cloud setup

1. From the repository root, run `./tao connect appwrite 'Apps/Hosted CRUD'` and press Return to automate. It uses the bundled Appwrite CLI 28.1.0. If that CLI is signed out, a browser opens for one-time Appwrite sign-in; create a free account there if needed. The CLI keeps its session in its own user configuration outside this project.
2. The command lists your organization's projects. Press Return to reuse the project already in `tao.connections.json`, or to create a new project under a generated `tao-hosted-crud-…` ID; typing an unknown ID asks for `yes` before creating it. A new project also asks for a permanent region (Return for `fra`). The Free plan allows two projects per organization.
3. It then creates a 15-minute key scoped to exactly the setup calls, which is never printed or stored, and uses it to register the Apple platform `dev.tao.hostedcrudspike`, enable email/password auth, and create serverless TablesDB database `tao_notes` with Notes table `notes`. It sets the Apple platform `dev.tao.hostedcrudspike`, enables email/password auth, and creates serverless TablesDB database `tao_notes` with Notes table `notes`. It sets required `ownerId` (Varchar 255), `text` (Text), `done` (Boolean), and `updatedAt` (Bigint) columns, an `ownerId` Key index, Row security, and only Users Create table permission. Existing resources are checked before reuse; a mismatched table is refused rather than overwritten.
4. The command writes the public endpoint and IDs to `tao.connections.json`. Typing `manual` at the first prompt keeps the older path instead: create the project and a project API key with those scopes in the Appwrite Console, then enter the endpoint, project ID, and key; that key is saved to the ignored, owner-only, unencrypted `.tao/connect-secrets.json` for reuse. Run `./tao connect run 'Apps/Hosted CRUD'`, sign in to Expo Go with the Expo account it names, scan the QR code, choose **Appwrite**, and create a test account. The React Native SDK checks the existing session with `account.get()` when restoring it.

Each local persistence key includes the endpoint, project, database, table, and account ID. After a successful online authentication check, the adapter caches the account ID and email. If a later `account.get()` fails with a transport error, `restore()` returns that cached identity and `open()` allows its notes to load while remote calls retry. A reachable 401 clears the cached identity. Offline restoration is local access to previously cached data, not proof that the server session is still valid; the SDK's session survival across a native restart remains untested.

Sign-out closes open connections before ending the server session and then removes the cached identity. Failed sign-out leaves the cache and server session in place, and the error is returned to the caller. Pending writes are retained under their owner's key for a later sign-in. AsyncStorage is not encrypted; do not put secrets in note text for this experiment.

The `ownerId` field is client-supplied and can be forged or changed with a direct SDK request; the query and adapter-side check are only UI filtering. Appwrite documents say a project user can grant only permissions they have and that Client SDK rows default to creator-only access. Those statements suggest that a forged `ownerId` alone does not let another account read the row, but only hosted hostile-client tests can establish that the intended isolation holds for this table and SDK version. Any contract requiring server-verified ownership or an immutable `ownerId` needs a server authority, such as an authenticated Appwrite Function that derives the owner from its execution context and owns writes. This experiment has not tested hostile direct requests, offline restart/replay, two-device reconciliation, iOS device behavior, or Expo Go native compatibility. These are required before any provider capability claim.
