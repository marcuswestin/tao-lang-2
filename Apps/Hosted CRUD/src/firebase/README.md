# Firebase + RxDB spike

This adapter uses Firebase email/password Auth, an RxDB database in Expo SQLite per Firebase project and UID, and live bidirectional replication with Firestore. Notes are stored at `users/{uid}/notes/{noteId}`. The RxDB plugin stores the local `id` as the Firestore document ID, not a field. CRUD writes go to SQLite first; RxDB replays them when replication can reach Firestore. Firestore's own persistence is not enabled in React Native.

1. From the repository root, run `./tao connect firebase 'Apps/Hosted CRUD'` and press **Return** at the Firebase config prompt to automate setup. If you have not used Firebase CLI on this computer, the command opens Google's sign-in page once. It reuses that login on later runs. No service-account JSON or pasted auth token is needed.
2. Enter the Firebase **project ID**. Use an ID from the list shown for an existing project, or enter a new unique ID and type `yes` when Tao asks to create it. Tao reuses a matching web app, or registers **Tao Hosted CRUD Demo** without Firebase Hosting. If the project has no default Firestore database, choose its permanent region when prompted. If it already has one, type `yes` only after reviewing that the pilot rules will replace the database's current rules. Tao then enables Email/Password auth, deploys `firestore.rules`, and saves the public web config.
3. Run `just hosted-crud`, scan its QR code in Expo Go, and choose Firebase. Register two accounts, create/update/delete notes, force-stop while offline after a write, restart, reconnect, and verify both accounts on separate devices. Also try direct Firestore writes into the other UID's path to test the rules.

The automation writes temporary deploy files under the ignored `.tao/firebase-connect/` directory. Firebase CLI stores its Google login in its own local user configuration (commonly `~/.config/configstore/firebase-tools.json`), outside the Tao project. That credential file is not encrypted by Tao. `tao.connections.json` contains only public Firebase web identifiers. Firebase's web API key identifies the app; it is not an admin credential.

For a project you configure manually, paste the entire Firebase SDK snippet or its `firebaseConfig` object at the same prompt. To enter the four public fields individually, type `manual`. In Firebase Console, press **Create app** (or **Add app**) and choose the Web app icon `</>`. Use **Tao Hosted CRUD Demo** as the nickname, leave **Also set up Firebase Hosting for this app** unchecked, and click **Register app**. On **Add Firebase SDK**, leave **Use npm** selected; Firebase is already installed here, so skip the install command. Copy the snippet and click **Continue to console**. You can find it later under **Project settings → General → Your apps → Web app → SDK setup and configuration → Config**. Manual config entry does not create Firestore, enable Auth, or deploy the rules; perform those steps in Firebase Console before running the app.

The rules give each authenticated UID access only to its notes subcollection and require RxDB tombstones and server timestamps. Do not deploy them over a project with other collections without composing and testing the full ruleset first.

The local SQLite database remains on the device after sign-out, keyed by project and UID. It is not encrypted. The adapter closes its active replica on sign-out, but the Firebase Auth SDK can switch accounts outside this adapter; the app should route all account changes through it. This is a spike: hosted rules, iOS Expo Go behavior, durable offline replay, conflicts, and cross-device isolation still need live verification.

References: [RxDB Firestore replication](https://rxdb.info/replication-firestore.html), [Firebase React Native support](https://firebase.google.com/docs/web/environments-js-sdk), [Firebase Auth persistence](https://firebase.google.com/docs/reference/js/auth), [community SQLite adapter](https://github.com/basepurpose/rxdb-sqlite).
