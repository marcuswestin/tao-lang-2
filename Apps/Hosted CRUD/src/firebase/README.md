# Firebase + RxDB spike

This adapter uses Firebase email/password Auth, an RxDB database in Expo SQLite per Firebase project and UID, and live bidirectional replication with Firestore. Notes are stored at `users/{uid}/notes/{noteId}`. The RxDB plugin stores the local `id` as the Firestore document ID, not a field. CRUD writes go to SQLite first; RxDB replays them when replication can reach Firestore. Firestore's own persistence is not enabled in React Native.

1. Create or open a disposable Firebase project. Press **Create app** (or **Add app**) and choose the Web app icon `</>`. Use **Tao Hosted CRUD Demo** as the app nickname, leave **Also set up Firebase Hosting for this app** unchecked, and click **Register app**.
2. On **Add Firebase SDK**, leave **Use npm** selected. The SDK is already installed in this app, so skip the `npm install firebase` command and sample initialization code. Copy `projectId`, `apiKey`, `appId`, and `authDomain` from the `firebaseConfig` snippet, then click **Continue to console**. If you leave before copying, find them under **Project settings → General → Your apps → Web app → SDK setup and configuration → Config**.
3. Run `./tao connect firebase 'Apps/Hosted CRUD'` from the repository root and enter those four values. It writes public web config to `tao.connections.json`; press Return at the optional service-account prompt. A service account is only for future backend tooling and stays out of the app bundle. In Firebase Console, open **Security → Authentication → Sign-in method**, enable **Email/Password**, and save. Open **Databases & Storage → Firestore**, then create the database.
4. Deploy `firestore.rules` as the project's Cloud Firestore rules. These rules give each authenticated UID access only to its notes subcollection and require RxDB tombstones and server timestamps. Do not merge them blindly into a project with other collections; compose and test the full ruleset first.
5. Run the Expo Go app, register two accounts, create/update/delete notes, force-stop while offline after a write, restart, reconnect, and verify both accounts on separate devices. Also try direct Firestore writes into the other UID's path to test the rules.

The local SQLite database remains on the device after sign-out, keyed by project and UID. It is not encrypted. The adapter closes its active replica on sign-out, but the Firebase Auth SDK can switch accounts outside this adapter; the app should route all account changes through it. This is a spike: hosted rules, iOS Expo Go behavior, durable offline replay, conflicts, and cross-device isolation still need live verification.

References: [RxDB Firestore replication](https://rxdb.info/replication-firestore.html), [Firebase React Native support](https://firebase.google.com/docs/web/environments-js-sdk), [Firebase Auth persistence](https://firebase.google.com/docs/reference/js/auth), [community SQLite adapter](https://github.com/basepurpose/rxdb-sqlite).
